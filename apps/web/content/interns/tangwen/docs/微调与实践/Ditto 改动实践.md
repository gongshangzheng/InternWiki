## 一、问题：视频源双重驱动

用**视频**（而非单图）驱动 Ditto 时，源视频自带的嘴动会叠加在音频驱动的唇动上——口型与音频错位，看起来"嘴在乱动"。

定位出三条泄露通道：

| 通道 | 泄露机制 |
|------|---------|
| exp 唇通道 | 逐帧参考的源帧 exp 偏移混入输出 |
| warp 源外观 f_s | warp 逐帧源纹理**自带源嘴形**——主导渲染 |
| x_d kp 回填 | LMDM 生成向量不含 kp，回填逻辑用逐帧源帧 kp，源张合时下颌骨架位移被带入 |

**术语速查**（代码注释确认）：x_d = 音频生成的驱动运动（265 维 = scale + 66×3 pose + t + 63 exp）；x_s = 源帧关键点；f_s = 源外观特征；M_c2o = canonical crop → 原图贴回仿射；kp = 21 点基准骨架。

## 二、演进线：每版方案 → 人工判定 → 裁决

### v1：运动通道隔离（作废）

**方案**：把 exp 唇通道（行 [6,12,14,17,19,20]）的基底换成源首帧，只保留音频 delta。

**判定**：渲染层**不可见**——因为 warp 的逐帧源外观 f_s 自带源嘴纹理，运动通道改了，外观通道还在渲染源嘴形。**作废**。

这次失败定位了外观通道才是主导泄露源。

### v2：整帧钉首帧（终裁主干）

**方案**：外观侧把 warp 的 f_s / x_s 整帧钉到**源首帧**（等同图像驱动形态），头动仍由 x_d 逐帧 pose 承载。

**判定**：人工判定通过，确立为主干。

### v3 / v4（均否决回滚）

- v3 嘴区像素合成：M_c2o 逆仿射重建逐帧 canonical crop，嘴区羽化替换首帧后重提 f_s——人工判定**变糊、眼神呆滞、pasteback 拼不齐**（根因：渲染在帧 0 crop 空间却用帧 t 的 M_c2o 贴回），否决
- v4 生成式两遍：先隔离再重生成——复杂度不值当，否决

**启示**：像素级修补在 warp 管线里会打架；表示层的干净钉帧胜过像素层的精细修补。

### kp 回填泄露修复

**问题**：`_mix_s_d_info` 用逐帧源帧 kp 回填——源视频张嘴时下颌骨架（含嘴部 6 点）逐帧位移，把源嘴几何带进生成目标。

**修复**：`x_d["kp"]` 钉回首帧骨架（`x_s0_kp`），头动由逐帧 pose 旋转承载，理论无损失。

**效果**：LSE-C 3.74 → **4.87**（+30%）。

### 开头 0.6s 音画错位修复

**问题**：HuBERT 滑窗的左上下文（3 块 × 0.2s）在开头用零填充稀释特征，LMDM 首窗又以源首帧为锚——开头约 0.6 秒口型与音频错位。

**修复**：`inference.py` 前置 15 帧静音垫，提取特征后丢弃对应帧，帧数守恒。默认路径同样生效。

## 三、指标总表

| 版本 | LSE-C ↑ | LSE-D ↓ |
|------|---------|---------|
| baseline（未隔离） | 3.44 | 11.12 |
| v2 整帧钉首帧 | 3.74 | 10.93 |
| v2 + kp 修复 | **4.87** | **8.81** |
| 单图模式上限（参考） | 5.01 | 8.75 |

距单图上限仅 0.14 / 0.06——视频源模式基本追平单图效果，同时保留视频的头动自然度。

## 四、工程形态

改动收敛为一个开关：`isolate_source_mouth`，**默认关**，仅视频源模式生效，**不改任何权重**——纯推理期管线改动，可随时回退。

## 面试追问预案

**Q：为什么 v2 整帧钉首帧反而比 v3 精细修补效果好？**

v3 的思路是"只修嘴区，其余保留视频源信息"——听起来信息保留更多。但它把问题拖进了像素空间：渲染发生在帧 0 的 crop 空间，而贴回用的是帧 t 的 M_c2o 仿射，坐标系不一致导致拼不齐、羽化边发糊。v2 直接在**表示层**解决问题：外观钉首帧后整条管线与图像驱动模式完全同构，不存在拼接问题。教训：在 warp 类管线里，坐标系一致性比局部信息保留更重要。

**Q：怎么确认"泄露"确实存在，而不是模型本身的口型误差？**

对照实验：用噪声驱动（无音频信号）跑 baseline，源视频张嘴时输出嘴仍跟随开合——这说明嘴动来自源视频而不是音频，泄露成立；开隔离后输出近似静止。定量复核：嘴动相关系数 0.995。**先复现现象，再谈修复**——和 Avatar Forcing 漂移定位实验（[微调实践](Avatar%20Forcing%20微调实践.md)）是同一套方法论。

**Q：既然 isolate 效果这么好，为什么默认关闭？**

两个原因。一是默认路径的回归口径：Ditto DDIM 无种子非确定，逐像素一致不可达，我们以"同码重跑方差"为标尺验证了默认路径无可测差异——改动不破坏原行为。二是功能定位：隔离是为"视频源 + 音频驱动"这个特定组合设计的，单图模式用户不需要。默认关、按需开，是推理期改动最安全的发布方式。
