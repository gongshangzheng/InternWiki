## 一、项目背景与个人定位

**项目定位**：为企业智能体（Agent）提供可直接调用的**多模态知识检索与问答能力**。系统承接 PDF、Word、PPT、Excel、Markdown、HTML、图片及**音视频**共 28+ 种异构资料，构建统一多模态向量空间，对外输出「检索 API + 流式问答 API」两类 Agent 可消费的能力接口。

**双链路架构**：

```text
离线摄取：上传 → FastAPI 建档 → Celery 异步投递 → OSS 下载 → 版面解析/结构化分块
          → text/image/desc 三路多模态向量化 → 写入 ADB-PG 向量库 → 状态回传

在线问答：提问 → 语义缓存 ∥ 知识库检索 → Dense+Sparse 并行召回 → 多模态精排
          → SCAR 邻接上下文扩展 → VLM 图文联合生成 → SSE 流式返回（带引用+耗时埋点）
```

**我的定位**：主导在线检索与生成链路（`retrieval_service` / `chat_service` / `query` API）的架构设计与全部编码实现，并负责离线摄取流水线的可靠性治理、音视频摄取轨从 0 到 1 建设，以及语义缓存体系落地。

## 二、核心技术亮点（STAR）

### 亮点 1｜设计多模态混合检索内核，构建 Agent 的「可靠感知层」

- **S（情境）**：企业资料中大量关键信息存在于扫描页、图表、PPT 与表格中。纯文本向量检索对这类内容几乎无法召回；而纯稠密检索对产品型号、编号、专有名词等精确匹配场景又极不稳定，Agent 拿到的资料常常"看起来相关但答不了"。
- **T（任务）**：建设一套同时覆盖「语义泛化」与「精确匹配」、且能理解视觉内容的检索内核，并保证任一外部模型故障时链路不中断。
- **A（行动）**：
  - **设计三重表示统一向量空间**：为同一语义元素建立 `text`（正文）/ `image`（页面视觉）/ `desc`（VLM 摘要）三类表示，基于 `qwen3-vl-embedding`（2560 维）编码后共享同一 `element_key`，实现跨模态同空间检索。
  - **重构召回为双路并行**：Dense 与 Sparse（jieba `cut_for_search` 分词，限流 12 token）拆分为独立 `AsyncSession` 经 `asyncio.gather` 并发执行，规避 SQLAlchemy 单 Session 不支持并发 SQL 的限制，将两路耗时由**串行叠加压缩为取最大值**。
  - **实现多表示去重与融合**：按 `element_key` 聚合多路命中，以 `image > desc > text` 优先级选取信息最完整的候选，并记录 `matched_reprs` 保留可观测性，彻底消除同一内容因多表示命中而**重复计票**的问题。
  - **搭建三级降级链路**：`qwen3-vl-rerank` 多模态精排（阈值 0.6）为主；精排未启用/超时/异常时自动降级 **RRF 融合**（k=60，仅依赖排名，无需两路分数同量纲）；RRF 为空时兜底单路结果。精排后若全部候选被阈值滤除，强制保留 Top1 并打标 `rerank_threshold_fallback_top1`，杜绝"高阈值导致零召回"。
  - **优化精排超时预算**：将「候选图片下载」与「精排 API 调用」拆分为两段独立超时预算（8s / 120s），解决原先共享预算下个别 OSS 下载卡顿会把整个精排拖到 120s 才触发降级的问题。
- **R（结果）**：
  - 降级触发时间由最坏 **120s 缩短至 8s（↓93%）**，未完成下载的候选自动退化为纯文本送精排，精排环节不再成为可用性单点。
  - 视频段精排经实测选型对比（原生视频 7.7s / 关键帧拼图 2.2s / 纯文本 1.1s），最终采用关键帧拼图方案，**精排延迟降低约 71%** 且保留足够视觉排序信号；将原生视频的高成本收敛到生成端仅 1~3 个最终命中处，实现"排序省钱、生成保真"。
  - 扫描件、图表页、PPT 等无文字层资料从**完全无法召回**变为可稳定命中。

### 亮点 2｜自研 SCAR 邻接上下文扩展算法，攻克 Chunk 语义割裂

- **S（情境）**：向量检索命中的是局部 Chunk，但完整语义常跨越多个 Chunk——标题与正文被拆开、图表与说明文字分离、图片命中后缺少邻近文本解释。Agent 据此生成的答案频繁出现事实残缺。传统"无条件取前后 N 个邻居"的做法则会引入大量无关噪声，挤占宝贵的上下文窗口。
- **T（任务）**：在扩展上下文的同时抑制噪声，让送入 VLM 的每一份资料都语义自洽。
- **A（行动）**：
  - **设计 SCAR 打分公式**，对每个邻居候选做语义连续性判定，仅保留通过阈值的邻居：

    ```text
    scar_score = query_score - λ × (1 - continuity)      # λ=0.1
    keep  ⟺  scar_score ≥ γ × hit_relevance              # γ=0.6
    ```

    其中 `continuity` 为锚点与候选的文本向量余弦相似度，实现「既相关于查询、又连续于原文」的双重约束。
  - **设计 deep_context_v4 图文锚定机制**：针对图片命中场景，沿 `prev/next` 指针**分层批量外推**（最多 16 跳）穿越连续图片，定位最近的文本锚点（等距时优先前文），解决"图片被多张无关图片包围、直接邻居取不到解释文本"的问题。
  - **以并查集（Union-Find）聚合资料组**：按摄取阶段固化的结构指针与 `photo_text_anchor_key` 合并连通分量，组内按「文档→类型→页码→阅读顺序」排序后拼接为单条完整资料，并将组内最高分图片提升至组级 `page_image_key`，确保 Agent 无需展开 `context_elements` 即可拿到与整组文本对应的视觉证据。
  - **重构邻居查询为按层批量**：由原先"每个锚点开一个 Session 并发查询"改为分层批量 SQL，DB 往返次数从 O(命中数×2) 降至 O(扩展层数)，并对全流程加异常兜底——SCAR 失败时静默跳过扩展、退回基础聚合，绝不影响主链路可用性。
- **R（结果）**：
  - 有效解决标题与正文被拆开、图表与说明文字分离、完整段落跨越多个 Chunk、图片命中后缺少邻近解释文本四类语义割裂问题；SCAR 过滤率与图文锚定成功率（`anchored/unanchored`）全量埋点可观测。
  - 上下文扩展在**保持召回完整性**的同时抑制无关邻居，避免了无条件扩展带来的上下文窗口浪费与噪声干扰。

### 亮点 3｜主导 Agent 就绪的服务接口层与 SSE 流式协议

- **S（情境）**：链路总耗时可达数秒至十余秒（原生视频 prefill 首 token 常 >10s）。原实现存在三大问题：① 从发起请求到检索+精排全部跑完，前端持续空白；② `references` 与首 token 之间长时间零字节流动，被网关空闲超时断连（前端表现为 `Load failed`）；③ 检索或生成阶段抛异常时，FastAPI 在 `StreamingResponse` 构造前返回非 SSE 格式的 HTTP 错误，客户端按 SSE 解析读不到任何 data 行，最终展示为空白回复。
- **T（任务）**：交付一套对 Agent/前端稳定可解析、全程有反馈、异常可感知的流式协议，并按调用方裁剪响应体。
- **A（行动）**：
  - **设计四段式 SSE 事件协议**：`status → references → content → done`，并将检索与生成两阶段的**任何异常统一捕获并转换为 `type: error` 事件**，保证整个响应体在任何情况下都是合法 SSE 流。
  - **实现连接级即时反馈**：连接建立即刻下发 `status: retrieving` 占位事件，消除首屏空白。
  - **引入 SSE 心跳保活**：以 `asyncio.Queue` 桥接生成流，`asyncio.wait_for` 5s 超时未取到 token 即下发 `: ping` 注释帧（客户端按 SSE 规范自动忽略），彻底解决长 prefill 期间被网关空闲超时切断的问题。
  - **打通同步 SDK 与异步框架**：模型客户端仅提供同步流，通过 `threading.Thread + queue.Queue + asyncio.to_thread(q.get)` 构建桥接器，将同步 SSE 转为 `AsyncGenerator`，避免阻塞 FastAPI 主事件循环。
  - **设计 `agent_multimodal` 响应投影**：面向 Agent 调用方从完整 metadata 中精选 12 个必要字段（`page_image_key`、`element_type`、`time_label`、`media_clip_url` 等），大幅压缩响应体；音视频段额外透出时间轴字段，解决"Agent 拿到 `page_num` 只是无法定位的段序号"问题。
  - **实现视频切片 URL 动态重签发**：入库的静态签名 URL 默认 1 小时过期，检索时基于同时留存的对象 Key 现签新 URL 覆盖，保证 Agent 每次拿到的都是新鲜可播放链接。
  - **建设全链路耗时埋点**：`done` 事件回传 `retrieve_ms` / `vlm_ttft_ms` / `vlm_generate_ms` / `total_ms`，配合 `X-Accel-Buffering: no` 禁止代理层缓冲。
- **R（结果）**：
  - 流式链路稳定性问题（空白回复、`Load failed` 断连）**全部收敛**；异常从"静默空白"变为客户端可捕获处理的显式错误事件。
  - 首屏反馈延迟从「等待全链路完成」降至**连接建立即刻**。
  - 四段耗时指标端到端透出，为性能归因提供直接依据；`agent_multimodal` 投影显著降低 Agent 侧 Token 与解析成本。

### 亮点 4｜落地两级语义缓存与写回准入治理，实现降本增效

- **S（情境）**：Agent 场景下高频 FAQ 类问题重复率高，每次都完整走「Embedding → 双路召回 → 多模态精排 → VLM 生成」，延迟与模型调用成本高企。但盲目缓存会导致个性化、强时效问题被错误复用，产生事实性错误。
- **T（任务）**：在显著降低延迟与成本的同时，通过准入治理确保缓存内容的正确性。
- **A（行动）**：
  - **设计两级缓存**：Exact 层（查询标准化 + `norm_hash` 精确命中，直接短路跳过向量检索）+ Semantic 层（pgvector 余弦相似度，阈值 0.90，Top5 候选，`ef_search=40`）。
  - **优化为缓存与检索并行竞速**：`asyncio.create_task` 同时发起缓存查询与知识库检索，**缓存命中即 `cancel()` 在飞的检索任务**，未命中则直接复用已在执行的检索结果——命中时不牺牲延迟，未命中时不增加延迟。
  - **构建分层写回准入（AdmissionService）**：规则层前置快速拒绝（空答案 / 兜底答案 / 超 800 字 / 命中"我的、余额、订单号、今天"等 15 个个性化时效关键词），可选轻量 LLM 层做二次判定（2s 超时，异常默认放行交人工审核兜底）。
  - **设计三态可信度模型**：`auto`（30 天软 TTL）/ `approved` / `pinned`（豁免 TTL，运营预置），支持运营干预与人工审核闭环。
  - **实现 `agent_id` 维度缓存隔离**：缓存以 `tenant_id + agent_id` 隔离，不同 Agent 人格互不污染；缺省 `agent_id` 则直接禁用缓存写入，避免误共享。
  - **攻克 ADB-PG 兼容性难题**：线上 ADB-PG 的 beam relation **不支持 `ON CONFLICT` 中仅更新部分列**，且计数器自增无法表达为 `col = EXCLUDED.col`。以 `UPDATE-then-INSERT` + `begin_nested()` 嵌套事务模拟 Upsert，并捕获 `IntegrityError` 处理并发插入竞态（败者折算进胜者计数），保证统计不丢。
  - **建设缓存运营数据闭环**：`cache_query_stat` 记录命中/未命中频次，提供 7 天窗口 Top 未命中查询排行，反向指导知识库补全。
  - **消除重复 Embedding**：以 `embedding_token`（Redis 暂存 300s）在检索与写回间复用同一查询向量。
- **R（结果）**：
  - 缓存命中时**完整跳过检索与生成两个阶段**，响应从「Embedding+双路召回+多模态精排+VLM 生成」的秒级链路降为**单次数据库查询 + 一次 content 事件**，同时节省 Embedding、Rerank、VLM 三类模型调用成本。
  - 全链路异常一律降级为 miss（缓存故障不影响主链路），配合准入规则与三态可信度模型，在提速的同时守住答案正确性。
  - 未命中查询排行为知识库运营提供了数据驱动的补全依据。

### 亮点 5｜治理异步摄取流水线的一致性与竞态问题

- **S（情境）**：文档解析涉及版面分析、OCR、VLM 调用，单文档耗时数十秒至数分钟。同步执行会长时间占用 Web Worker 并触发网关超时；异步化后又暴露出跨进程竞态导致的**孤儿向量数据**（已实测复现）。
- **T（任务）**：建设可靠、幂等、无脏数据的异步摄取流水线。
- **A（行动）**：
  - **重构为 Celery 异步任务链路**，API 侧建档后立即返回 `document_id / track_id / task_id`，前端轮询状态；Worker 配置 `task_acks_late=True`（完成后确认，异常退出可重新入队）、`worker_prefetch_multiplier=1`（避免长任务分配不均）、软/硬超时 540s/600s 双保险、失败重试 3 次（间隔 30s）。
  - **修复投递时序竞态**：将 `db.commit()` 严格置于 `.delay()` 之前——原先先投递任务，Worker 可能在 API 事务提交前查询文档，误判记录不存在。
  - **攻克孤儿向量数据（核心贡献）**：`delete_document_task` 只清理 `chunks_multi`，无法感知或中止一个已在运行的 ingest 任务；用户在解析期间删除文档后，ingest 任务仍会继续写入向量。**在真正写入向量前增加 `_document_still_exists()` 二次存在性复查**，不存在则跳过写入，从根源消除孤儿数据。
  - **建设双重幂等防护**：已 `completed` 直接跳过；处于 `parsing/chunking/embedding` 且 `task_id` 与当前任务不一致时跳过，防止同一文档被多任务并发摄取。
  - **实现内容级去重**：SHA-256 内容哈希在 `tenant_id + kb_id` 范围内比对，重复内容直接失败并回传冲突文档信息。
  - **设计 Worker 同步引擎 + API 异步引擎双连接模式**（`pool_pre_ping=True` 规避连接闲置失效），契合"文档解析库多为同步"的现实，简化 Worker 事件循环管理。
  - **补齐向量生命周期**：写入前先 `delete_document_entries_sync` 清旧再批量插入，天然支持文档重试与重新解析；全流程 `DocumentEvent` 状态机事件留痕，进度实时回写。
- **R（结果）**：
  - HTTP 接口响应从数十秒至数分钟的阻塞降为**毫秒级立即返回**，Web Worker 不再被长任务占用。
  - 孤儿向量数据、重复摄取、投递时序竞态三类一致性缺陷全部闭环，并沉淀 `test_ingest_race_guard_unit` / `test_vector_lifecycle` 专项回归测试。

### 亮点 6｜从 0 到 1 建设音视频多模态摄取轨，攻克模型幻觉污染

- **S（情境）**：知识库需接入会议录音、培训视频等音视频资料。此类内容与文档形态差异极大（无页码、有时间轴），且实践中发现 omni 模型对**无声输入会幻觉出具体的音乐/音效描述**——虚构内容一旦入库即成为可被检索的假信息，会直接污染 Agent 的回答。
- **T（任务）**：将音视频对齐至既有多模态元素模型，并阻断幻觉内容入库。
- **A（行动）**：
  - **设计与文档元素同构的媒体元素模型**：段级文本描述作为语义锚点，`time_label / start_ms / end_ms` 承载时间轴（替代页码定位），复用同一向量表与检索链路，零成本接入既有 Agent 接口。
  - **构建分段策略**：音频按 ASR 句子驱动聚合（目标 90s / 上限 800 字 / 静默间隔 2s 断句）；视频按 30s 固定时间网格切分（上限 240 段），每段抽 4 帧合成关键帧拼图作为视觉锚。
  - **接入 Paraformer-v2 异步文件转写**：提交 + 轮询模式（5s 间隔，最长 1800s），前置时长（2h）与体积（2GB）闸门，避免超长素材拖垮摄取与账单。
  - **设计 ASR 信息量闸门与描述降级**：文档级按字/分钟密度（<40 字/分）、段级按绝对字数（<15 字）判定"转写不足"，自动改由 `qwen3-omni-flash` 直接"听"音频生成描述（走 base64 不依赖公网 URL），补上只存在于语音中、画面上看不到的信息。
  - **攻克幻觉污染（核心贡献）**：在描述前引入 **ffmpeg `silencedetect` 静音闸门**（噪声阈 -35dB，最小时长 1s，静音占比 >0.9 才跳过描述）。基于实测数据设定策略——阈值有意偏高，因为"漏放一段静音只多一条废描述，误杀一段有声内容却是永久检索不到"。
  - **实现原生视频编码与关键帧双路降级**：视频段切片上传后交 `qwen3-vl-embedding` 原生 video 编码；超 50MB 上限或拿不到公网 URL 时自动降级关键帧编码，保证任何环境下都能完成向量化。
- **R（结果）**：
  - 静音闸门实测**在 `mean_volume ≤ -56dB` 时 100% 检出、-45dB 起完全放行**；对照真实讲话视频静音占比最高仅 4.7%（绝对静音为 100%），阈值留有极大安全余量，在阻断幻觉入库的同时**零误杀有声内容**。
  - 知识库能力边界从「文档」扩展至「文档 + 音视频」，且音视频段可通过 `media_clip_url` 直接回传可播放切片，Agent 可给出带时间戳的精确溯源。
  - 沉淀 23 个音视频摄取专项单测，为该轨道建立回归防线。

## 三、工程化与质量保障

| 维度 | 关键实践与个人贡献 |
|---|---|
| **多租户隔离** | `tenant_id / kb_id / document_id` 三级隔离，全部检索强制携带过滤条件；图片接口校验对象 Key 归属，阻断跨租户越权访问 |
| **向量存储** | 兼容生产 ADB-PG 原生向量能力与本地 pgvector；HNSW 索引（`m=16, ef_construction=64`）；高维（>2000）场景启用 `halfvec` 降低存储成本；关闭框架自动建表（`perform_setup=False`），DDL 由项目 SQL 显式维护；配置 `lock_timeout` 10s / `statement_timeout` 180s 防慢查询拖垮连接池 |
| **图片资源治理** | 设计 PageStore 屏蔽 OSS 与本地存储差异，统一 Key 格式；三级缓存（本地磁盘 → Redis 跨实例二进制 → OSS 权威源）；**同 Key `asyncio.Lock`** 防并发重复下载；**`.part` 临时文件 + `os.replace()` 原子写**防读到半成品；TTL 24h + 2GB 容量上限 + 按 mtime 淘汰 |
| **定时治理** | Celery Beat 独立进程（规避 Worker 扩容后重复投递）：每日 03:00 清理过期语义缓存，每小时第 15 分钟清理图片磁盘缓存，超容量时附加淘汰并打 WARNING 告警 |
| **解析路由** | 按扩展名路由至 `naive / spreadsheet / markdown / presentation / picture` 五类 Chunker；Word/PPT/HTML 转 PDF 复用统一版面链路；**Excel/CSV 坚持原生结构化解析**，避免转 PDF 丢失多 Sheet、公式、合并单元格与内嵌图片锚点 |
| **性能优化** | Markdown 远程图片由逐张串行（单图 30s 超时）重构为**并发预取（并发 4，连接 3s / 读取 10s 预算）**，消除 Worker 长时间卡在 chunking；VLM 图片编码经 `asyncio.gather + to_thread` 并发处理，避免同步缩放阻塞事件循环；生成端图片证据限流 3 张、长边 1280，防 payload 过大导致请求超时 |
| **成本控制** | 贫瘠页面（文字层 <100 字符）才触发 VLM 摘要，按需调用；装饰性图片（OCR 文本 ≤8 字符）直接跳过标注；分批向量化（batch=16）控制内存峰值与单次请求大小 |
| **测试保障** | 沉淀 **84 个单测与集成测试**，覆盖摄取竞态防护、向量生命周期、多模态检索、音视频摄取、表格/Markdown 分块、图片代理等关键路径 |
| **部署运维** | Docker Compose 编排 postgres / redis / api / worker / beat，`depends_on: service_healthy` 控制启动顺序；API/Worker/Beat 共享镜像、异化启动命令，实现职责分离与独立扩容；接入 Diamond 配置中心实现线上参数热调整与"一键熄火"开关 |

## 四、能力沉淀

- **Agent 能力供给设计**：理解 Agent 消费侧诉求，主动设计 `agent_multimodal` 响应投影、`agent_id` 缓存隔离维度、时间轴溯源字段，而非简单暴露内部数据结构。
- **上下文工程**：自研 SCAR 打分与图文锚定机制，在"召回完整性"与"上下文窗口噪声"间取得平衡——这是决定 Agent 回答质量的关键环节。
- **模型编排与降级设计**：串联 Embedding / Rerank / VLM / OCR / ASR / Omni 六类模型服务，为每一处外部依赖设计独立超时预算与降级路径，无单点故障。
- **成本与延迟的工程权衡**：基于实测数据（而非直觉）做技术选型，如精排用关键帧、生成用原生视频；静音闸门阈值按"误杀代价 >> 漏放代价"倾斜设定。
- **数据一致性与竞态治理**：具备定位并修复跨进程竞态、孤儿数据、并发插入冲突等隐蔽缺陷的能力，并以专项测试固化。
