## Context

现有数字人文档强调已选方案和已验证结论，但模型探索过程本身也是决策证据。一次“效果糊”可能来自模型、资产、音频、分辨率、部署资源或运行参数；把它直接标为失败会误导后续选型。当前用户计划重新运行 ExOmni-2D 与 MoDA，因此文档需要先保存观察和复现协议，再等待可比结果。

## Goals / Non-Goals

**Goals:**
- 新建一篇模型探索与未采纳实验复盘文档。
- 用状态流转表达证据强度，避免永久化“失败”标签。
- 对每个模型记录可复现条件、观察维度、对照、证据路径和下一步。
- 为 ExOmni-2D、MoDA 建待复跑占位，不捏造指标或最终判断。
- 让复跑结果能直接补进同一张模型记录表。

**Non-Goals:**
- 不建立自动化实验数据库或修改评测框架。
- 不汇总未证实的历史口头结论。
- 不在本 change 运行 ExOmni-2D 或 MoDA。
- 不把一次主观观察换算成客观指标。

## Decisions

### 使用“模型探索与未采纳实验复盘”而非“失败模型”

模型的状态取决于证据而非名称。采用四态：
- `待复跑`：已有口头/初步观察，缺少可比复现实验；
- `初步观察`：已产生输出但对照不完整；
- `已复现`：同协议重复得到一致现象；
- `已否决`：在明确场景、协议和证据下，决定当前不采用。

状态可以向前推进，也允许复跑后回退或翻案。

### 记录可比较条件，而非只写“效果好/差”

每个模型条目固定记录：版本与来源、资产、音频、分辨率/帧率、硬件/显存、关键参数、观察维度、对照模型、证据路径、当前结论、下一步。比较前至少对齐资产、音频、输出规格；无法对齐时必须写明差异，结论只限该次运行。

### 分开“模型问题”“配置失败”“评测无结论”

文档按三种实验结果组织：
- 当前未采用：输出可运行但未超过对照；
- 配置/部署失败：没有有效输出，不能评价模型质量；
- 结论不足：输出存在，但输入或指标不可比。

这样能避免把环境问题归给模型。

### ExOmni-2D 和 MoDA 只填占位

- ExOmni-2D：状态 `待复跑`，初步观察“输出偏糊”；
- MoDA：状态 `待复跑`，初步观察“可运行，当前主观上弱于 Avatar Forcing”。

两条均不写分数、证据路径或最终结论，下一步统一为同资产/同音频/同规格复跑并填写结果。

## Risks / Trade-offs

- [待复跑观察被读成最终结论] → 每条顶部显示状态和证据等级，明确“不可用于模型排序”。
- [表格字段过多导致不更新] → 仅保留影响比较的最小字段，详细日志存外部证据路径。
- [不同模型无法完全同环境运行] → 允许记录差异，但禁止作强弱排序。
- [失败经验变成情绪化批评] → 结论必须指向观察、证据和下一步。

## Migration Plan

1. 新建文档和复盘模板。
2. 加入 ExOmni-2D、MoDA 待复跑占位。
3. 用户按同资产、同音频、同输出规格复跑。
4. 复跑后更新状态、证据路径、观察表和当前决策。
